# 演示与验收指南

## 3–5 分钟演示脚本

| 时间 | 操作 | 解说要点 |
|---|---|---|
| 0:00–0:30 | 登录，打开评测数据集 | 25 条自建模拟业务问题，每条有检查点与证据来源，发布后内容固定 |
| 0:30–1:00 | 首页运行 A/B 演示，打开批次 | 后台实际调用本地 HTTP Agent，结果持久化；关闭页面不停止任务 |
| 1:00–1:40 | 版本对比 | 同集同规则，显示改善、退化、维持、不可比；未知不算失败，不掩盖覆盖率 |
| 1:40–2:30 | 筛选退化，打开 CS-007 的 B 详情 | 管理员转移回答缺少必要业务条件；同时查看回答与模拟检索/模型步骤 |
| 2:30–3:00 | 打开 CS-021、CS-023 或 CS-024 | 分别展示工具参数错误、工具观测缺失、调用异常，说明能力边界 |
| 3:00–3:30 | 人工复核一个成功调用的案例 | 必须填理由，旧评分保留，可查看历史 |
| 3:30–4:30 | 生成脱敏报告并下载 | 文件脱网可开，记录版本 hash、分母、成本覆盖率、不可比案例和限制 |

## 样例故障设计

- CS-001–006：A 回答不符合业务要点，B 修复。
- CS-007：A 正确，B 退化，展示版本改进不等于每个 case 改进。
- CS-020：特殊合同要求人工审核，默认 UNKNOWN。
- CS-021：两版均给出错误工具参数，规则失败。
- CS-023：返回回答但缺少工具 trace，无法评估工具正确性。
- CS-024：模拟 HTTP 503，独立记录调用错误。
- CS-025：无 usage，费用未知；不作为零成本。

以上均为明确设计的模拟案例，不是已发现的企业事故。

## 数据集导入

“评测数据集 → 导入问题集”，选择 `demo-data/customer-service-25.jsonl` 或粘贴 JSONL。校验通过后生成草稿，审核后发布。修订通过重新导入新版本完成。重复 case_id、缺少 input、无效 checks 返回行号。

## 企业 HTTP 接入

1. 在服务启动环境配置 `AGENT_ALLOWED_ORIGINS=http://10.0.0.8:9000` 等精确 origin。
2. 配置 `AGENT_SECRET_CUSTOMER` 为认证密钥。
3. 管理员在 Agent 配置添加固定 IPv4 的接口地址；secret_ref 填 `AGENT_SECRET_CUSTOMER`，不要填写密钥正文。
4. 根据企业实际协议实现映射，使请求/响应满足 `contracts/API与数据契约.md`。
5. 点击连接测试；确定价格与 usage 能力，缺失时保留未知。
6. 只使用授权脱敏样本及测试环境，运行后记录真实反馈与受控版本范围。

## 本地备份与恢复

先停止 Java 服务，再执行 `powershell -File scripts/backup.ps1`。脚本会检查 H2 文件是否被占用，备份保存在 backups 下。恢复时先保留现有 data 目录到另一个备份位置，再将备份解压至项目根目录，确保 `data/agentlens.mv.db` 存在，然后启动。

MySQL 模式使用 mysqldump 或企业现有备份机制，数据库凭据通过安全配置注入。该路径需在实际 Docker/MySQL 环境独立验证。

## 提交前检查

- 以实际构建的 release 版本演示，源码、截图、报告和录屏一致。
- 标记 mock 与企业真实数据，禁止将模拟改善率写成企业收益。
- 不把 .env、数据库、缓存或企业原始数据随源码提交。
- 离线演示先验证 Java、可执行 JAR 和本地端口；无需现场下载依赖。
- 演示已保存的历史批次时说明其运行时间。
- 本项目提供系统和技术资料；学校正式申报书、成员信息、企业访谈/授权及真实试点报告需按实际事实填写。
